## História

Como mantenedor, quero que GitHub Actions execute os gates de qualidade em pushes e pull requests, para que mudanças sejam verificadas em CI reproduzível antes de integração.

## Valor e contexto

A Story 0.5 definiu e executou gates localmente, mas não havia workflow em `.github/workflows/`; resultados locais não são evidência de CI. O pipeline oficial solicitado é GitHub Actions. O proprietário aprovou aceite temporário específico para SEC-009 até 2026-10-27; o advisory permanece HIGH, aberto e não corrigido, e não pode ser ocultado como correção. Ausência de execução remota deve ser reportada como pendente até um push/PR acionar o workflow no GitHub.

## Critérios de aceite

- [ ] **AC1 — Disparadores e escopo:** existe workflow versionado em `.github/workflows/` acionado em `push` e `pull_request` para branches do projeto; execuções concorrentes da mesma ref cancelam a execução anterior quando seguro. O workflow não solicita secrets de produção nem acessa serviços externos do bot.
- [ ] **AC2 — Instalação reprodutível:** em runner Linux suportado, `npm ci` instala exatamente o lockfile; ausência/inconsistência do lockfile causa falha explícita e não é contornada por `npm install`.
- [ ] **AC3 — Qualidade estática e testes unitários:** CI executa `npm run lint`, `npm run typecheck` e `npm test`; no passo unitário `DATABASE_URL` e `AIOX_TEST_DATABASE` estão ausentes, e o relatório deixa claro que testes PostgreSQL não executados nessa etapa são skipped/intencionais.
- [ ] **AC4 — Integração PostgreSQL efêmera:** CI executa `npm run test:integration` usando somente o harness Compose descartável já existente; verifica migrations, resultado dos testes e cleanup do container mesmo em falha tratável. Nenhum banco persistente ou URL/secrets externos é fornecido.
- [ ] **AC5 — Build e Prisma:** CI executa `npm run build` e `npx prisma validate`; esses resultados são gates separados e não substituem os testes comportamentais.
- [ ] **AC6 — Auditoria com waiver delimitado:** CI executa auditoria de dependências para produção e conjunto completo e mantém a saída bruta disponível. O único waiver é para `GHSA-ggr8-5vv4-36mx` nos **três findings** registrados na Decisão Humana 005, exclusivamente para `deepmerge-ts@7.1.5` pela cadeia `prisma@6.19.3 → @prisma/config@6.19.3 → deepmerge-ts@7.1.5`, até 2026-10-27 inclusive. O resumo identifica separadamente os três findings como HIGH, OPEN e WAIVED temporariamente; nunca declara audit limpa, PASS sem ressalva ou vulnerabilidade corrigida. Encontrar advisory, pacote/versão ou caminho de dependência adicional, contagem diferente de três, severidade adicional/maior ou o finding após 2026-10-27 faz o gate falhar. Não usar `continue-on-error`, `|| true` ou supressão ampla. Expirada a decisão, só correção suportada ou novo aceite formal vigente pode permitir o gate.
- [ ] **AC7 — Relatório CI verdadeiro:** execução de cada job/step tem status rastreável no sumário nativo do GitHub Actions; falha ou cancelamento não aparece como PASS. O workflow não afirma resultados remotos antes de ser executado no GitHub. Evidência local e evidência remota são identificadas separadamente.
- [ ] **AC8 — GitHub Actions é o CI documentado:** documentação e `npm run quality:pipeline` deixam de tratar CodeRabbit como gate/requisito e identificam GitHub Actions como CI oficial; o relatório local pode indicar workflow configurado/não executado localmente, sem alegar execução remota. Nenhuma etapa opcional de scanner de segredos substitui qualquer gate de CI desta story.
- [ ] **AC9 — Permissões mínimas e integridade:** workflow e jobs declaram somente permissões GitHub necessárias (preferência `contents: read`); actions de terceiros são referenciadas por versão imutável/SHA conforme convenção de segurança do repositório, sem token de escrita, deploy, publicação ou criação de PR.
- [ ] **AC10 — Validação do workflow:** YAML foi validado localmente e uma execução real em push terminou verde; QA/Architect ainda precisam revisar matriz de jobs, isolamento de banco, waiver e evidência antes de fechar a story. A conclusão hosted satisfaz apenas a exigência de execução do AC10, não substitui os pareceres independentes.
